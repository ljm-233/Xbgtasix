# 加密地图：哪些归档能读、哪些读不了

工具：[tools/packaging/encryption_survey.py](../tools/packaging/encryption_survey.py)
（按 4 KB 块分类：全零 / zlib 可解 / 文本 / 二进制结构 / 高熵）

每个归档只读前 32–64 MB 采样，样本足够反映整体结构。

| 归档 | 高熵（疑似加密/专有压缩） | 二进制结构（明文） | 结论 |
|---|---|---|---|
| `levels.rpf`（76 GB） | **0.8%** | **99.1%** | 几乎全明文 |
| `navmeshes.rpf`（6.7 GB） | 3.9% | 96.1% | 几乎全明文 |
| `movies.rpf`（8.8 GB） | 11.7% | 88.3% | 大部分明文 |
| `script.rpf`（4.4 MB） | 15.3% | 19.0%（+ 65.6% zlib） | 大部分可解 |
| `audio.rpf`（28.5 GB） | 20.3% | — | 大部分明文 |
| `movies`/`anim.rpf`（4.4 GB） | 27.6% / 37.6% | — | 混合 |
| `shaders.rpf`（412 MB） | 30.4% | — | 混合（着色器容器本身明文） |
| `data.rpf`（482 MB） | 44.2% | — | 混合 |
| `textures.rpf`（193 MB） | 61.3% | — | 偏高 |
| `packs.rpf`（4.8 GB） | 62.6% | — | 偏高 |
| `common.rpf`（6.6 MB） | 64.3% | 23.4% | 偏高 |

## 三个结论

**1. “大部分 RPF 被加密”不成立。**
最重的两个包（`levels.rpf` 76 GB、`navmeshes.rpf` 6.7 GB）**99% 是明文二进制**。
加密比例在不同包之间从 0.8% 到 64.3% 不等，没有一个包是"全都加密"。

**2. 真正稳定被加密的只有目录表（TOC）。**
每份归档 64 字节头之后的目录区都是高熵、16 字节对齐、无重复块 —— 这才是需要密钥的地方。
它只占文件极小一部分（`common.rpf` 38 KB / 6.6 MB）。

**3. 挡住我们的不是加密，是格式。**
`levels.rpf` 里 33 MB 明文几何，我们照样读不出来 —— 因为没有 RAGE9 `.#dr` meshlet
格式的解析器。而 PercyStar 有，所以它能导出模型。

> 换句话说：**数据是送的，钥匙是钥匙，解析器才是门槛。**

## 这对项目意味着什么

| 想做的事 | 需要 | 现状 |
|---|---|---|
| 看 XML / 脚本 / 文本 | 解 zlib | ✅ 已有（`rpf_carve.py`） |
| 看模型 / 几何 | RAGE9 模型格式解析器 | ❌ 没有（PercyStar 有） |
| 按路径读资产 | RPF9 目录表密钥 | ❌ 密钥在缺失的 exe 里 |
| 让游戏跑 | exe | ❌ 包内唯一缺失项 |

**所以“没有密钥”不等于“什么都拿不到”**：能拿的是满载的明文几何与文本，
拿不到的是"按名字索引"和"运行"。
