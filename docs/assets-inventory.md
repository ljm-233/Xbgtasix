# 资产清单：现在手里能拿到什么

全部来自本地包，工具：PercyStar（导出）+ 本仓库的 `t8_model`（渲染）/ `t12_sheet`（拼图）。

## 模型

| 类别 | 数量 | 来源 | 备注 |
|---|---|---|---|
| 载具 | **333** | `levels.rpf` | 最大 `flatdeck.obj` 48 MB；`jet` 79.8 万顶点 / 26.6 万三角形 |
| 人物/服装 | 160 | `packs.rpf` | 含 `cargo/jacket` 等衣物，多为 `.#dr` meshlet |
| 人物边界代理 | 若干 | 同上 | 只有几十顶点，是碰撞包围盒不是网格 |

批量渲染 + 拼图：

```bash
# 渲染（每个模型一张 512x512）
./t8_model.exe <model.obj> <texture.png> <out.png>
# 拼成网格
./t12_sheet.exe <png目录> <sheet.png> 160 8
```

## 贴图

| 来源 | 数量 | 是否有名字 |
|---|---|---|
| `textures.rpf` | 1354 张 | **有**（`ffx_*`、`settings_*`、`waterfog*`… 主要是 UI/特效/雾） |
| `data/ttdb/*.ttpf` | 57 个数据库 / **57 GB** | **没有**，导出名是 `tex_00000_512x512_BC7` 这种序号 |

单个文件就有多少？`peds_loose.ttpf`（135 MB）= **6204 张**。peds 一类合计 5.6 GB。

**结论**：服装贴图**确实存在且能导出**（布料、迷彩、针织纹路都看得到），
但**没有名字**——TTPF 里的条目是按索引组织的，名字在加密的目录表里或根本没存。

这解释了为什么按名字给模型找贴图会全军覆没：
不是贴图不在，是**贴图没有名字**。

## 缺什么

| 缺口 | 影响 |
|---|---|
| `game_scarlett_master.exe` | 不能运行；也拿不到 RPF 目录表密钥 |
| TTPF 的条目名 | 贴图与模型无法自动对应（只能人工看拼图挑） |
| `.#dr` 格式解析器 | 我们自己的代码还不能直接读模型（PercyStar 可以） |
